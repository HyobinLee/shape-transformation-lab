## 1. 무엇을 만들고 있는가

**고등학교 수준의 기하·대수 개념(일차변환, 대칭이동, 복소평면)을 학생이 값을 바꿔 가며 눈으로 확인하는 교육용 웹 실험실.**

핵심 명제는 교과서에 문장으로만 적혀 있는 다음 사실들을, 학생이 직접 손으로 조작해서 발견하도록 만드는 것입니다.

| 섹션 | 관찰시키려는 명제 |
| --- | --- |
| 1. 행렬을 통한 일차변환 | 2×2 행렬은 평면 전체를 늘이고/찌그러뜨리는 하나의 "동작"이다. 직선·평행성·꼭짓점 개수는 보존되지만 길이와 각은 아니어서 **원은 타원이 된다.** **행렬의 열은 기저벡터가 간 자리이고, 넓이비는 행렬식이다.** 비가역행렬에서는 평면 전체가 원점을 지나는 직선 하나로 눌리고, **어떤 직선은 점 하나로 무너진다.** |
| 2. 행렬을 통한 대칭/회전변환 | **두 번의 축 대칭 = 한 번의 회전이며, 회전각은 두 축이 이루는 각의 2배다.** |
| 3. 복소평면에서의 이동 | 복소함수 $w = f(z)$ 는 도형을 통째로 옮기는 사상(map)이다. 자취 $x^2+y^2=1$ 이 $f$ 를 지나면 무엇이 되는가. |
| 4. 복소평면에서의 회전/평행이동 | **평행이동→회전→평행이동의 합성은 (대개) 다른 점을 중심으로 하는 하나의 회전이다.** 그 중심은 어디인가. |
| 5. 일차변환의 고유공간 <sub>(1 심화)</sub> | 변환이 **통째로 제자리에 두는 직선**이 있다. 두 개일 수도, 하나뿐일 수도, 아예 없을 수도, 평면 전체일 수도 있다. **없는 경우가 곧 회전이다.** |
| 6. 거울을 몇 번 놓아야 하는가 <sub>(2 심화)</sub> | 평면의 모든 등거리변환은 **평행이동·회전·대칭·미끄럼대칭 넷 중 하나**다. 거울 개수의 홀짝이 방향 보존을 가른다. |
| 7. 되풀이하면 어디로 가는가 <sub>(4 심화)</sub> | 고정점에서 재면 이 변환은 **그냥 곱하기 하나**다 — $z_n - z^* = \rho^n(z_0 - z^*)$. 수렴·회전·발산이 $\lvert\rho\rvert$ 하나로 갈린다. |
| 8. 원은 원으로 간다 <sub>(3 심화)</sub> | $w=\frac{az+b}{cz+d}$ 는 원과 직선을 원과 직선으로 보낸다. **직선은 무한대를 지나는 원이다.** |

심화 섹션(5~8)은 기초를 **대체하지 않고 병존**합니다. 기초는 교과서의 문장을 눈으로 확인하는 자리이고, 심화는 그 뒤에 숨은 구조를 학생이 직접 찾는 자리입니다. 예를 들어 §2 는 원점을 지나는 축만 다루지만, §6 에서 축을 원점 밖으로 옮기면 평행이동과 미끄럼대칭이 새로 등장합니다.

각 섹션의 헤더 문구가 이 의도를 그대로 드러냅니다 — 예: `"평행이동&회전이동&평행이동은 회전이동일까요? 회전의 기준점은?"`
([section4_rotation_translation.py:8](../section4_rotation_translation.py#L8)). 답을 알려주지 않고 **질문을 던진 뒤 도구를 쥐여주는** 것이 이 앱의 일관된 화법입니다.

## 2. 구성

```text
app.py                                # 사이드바 라우터 (유일한 진입점)
lab_ui.py                             # 섹션 공통 화면 배관
expression_parser.py                  # 섹션3이 쓰는 안전한 수식 파서
gemini_client.py                      # 섹션1 탐구 챗봇이 쓰는 네트워크 경계
section1_transformation_by_matrix.py  # run_transformation_by_matrix()
section2_symmetry_rotation.py         # run_symmetry_rotation()
section3_complex_plane.py             # run_complex_plane()
section4_rotation_translation.py      # run_rotation_translation()
section5_eigenspace.py                # run_eigenspace()
section6_isometry.py                  # run_isometry()
section7_orbit.py                     # run_orbit()
section8_mobius.py                    # run_mobius()
test/                                 # pytest 없이 실행하는 검증 스크립트 8개
backup/                               # (미사용) 섹션 분리 이전 버전, Dash 실험
requirements.txt
```

섹션 파일이 아닌 것이 셋 있고, 셋 다 이유가 다릅니다.

[expression_parser.py](../expression_parser.py) 는 수업 내용이 아니라 **보안 경계**입니다. 감사(audit)와 테스트가 가능하도록 한곳에 모아 두는 편이 섹션 안에 흩어 두는 것보다 낫다고 판단했습니다.

[gemini_client.py](../gemini_client.py) 는 같은 논리의 **네트워크 경계**입니다. 키·타임아웃·재시도·캐시가 섹션 안에 흩어지면 그 섹션이 무엇에 대한 수업인지 읽을 수 없게 됩니다. 의존성은 늘리지 않았습니다 — Gemini 는 그냥 JSON 을 받는 HTTPS 엔드포인트이므로 표준 라이브러리 `urllib` 로 부릅니다. **학생이 읽는 문구는 여기 두지 않습니다**; 실패했다는 사실만 예외로 알리고 그것을 어떤 말로 전할지는 섹션이 정합니다.

[lab_ui.py](../lab_ui.py) 는 **화면 배관**입니다. 섹션이 넷에서 여덟이 되면서 축 설정·그래프 `key`/`uirevision`·자취·무지개 대응 같은 상용구가 여덟 벌씩 복사되게 됐는데, 한 군데만 빠뜨려도 그 섹션만 깜빡이거나 그 섹션만 색이 어긋납니다. 그래서 **배관만** 옮기고 경계를 엄격히 그었습니다.

- 들어가는 것: 어떻게 보이는가 (등축 축, 자취 적재, 무지개 재표본화, 채널 배분)
- 들어가지 **않는** 것: 무엇을 보여 주는가 (변환·판정·공식) 와 **학생이 읽는 모든 문구**

리뷰 기준은 셋입니다. ① `lab_ui.py` 안에 한국어 설명 문장이 있으면 잘못 들어간 것 ② 변환·판정·공식이 있으면 잘못 들어간 것 ③ **섹션 파일만 읽고도 그 수업이 통째로 이해되어야** 한다. 셋째가 깨지는 추출은 되돌립니다.

### 구조적 계약

[app.py](../app.py) 는 **라우팅만** 합니다. 사이드바 라디오 선택값을 `run_*()` 호출로 분기하는 것이 전부이며, 상태도 로직도 갖지 않습니다.

```python
if menu == "1. 행렬을 통한 일차변환":
    run_transformation_by_matrix()
```

각 섹션은 **인자 없는 `run_*()` 함수 하나**를 노출하고, 그 안에서 입력 위젯·계산·시각화를 모두 처리합니다. 섹션 간에 공유되는 것은 없습니다.
결과적으로:

- **섹션 하나를 고쳐도 다른 섹션이 깨질 수 없다.** 이것이 이 구조가 선택된 이유입니다.
- 수학은 여전히 **의도적으로 중복**됩니다. 예를 들어 고정점 공식 `fixed_point()` 가 §4 와 §7 에 따로 있습니다. 각 섹션이 하나의 독립된 수업 자료처럼 읽히는 편이, DRY 하지만 공통 모듈을 오가며 읽어야 하는 코드보다 이 프로젝트의 목적에 맞습니다. 대신 [test/test_orbit.py](../test/test_orbit.py) 가 **두 복사본이 같은 답을 내는지** 확인합니다.

### 화면 관용구

여덟 섹션이 모두 같은 레이아웃 문법을 따릅니다.

- `st.columns([...])` 로 **왼쪽 = 입력, 오른쪽 = 시각화** 2단 분할 (`[1.4, 0.3, 2]`, `[1, 1.5]`, `[1, 1]` 등 섹션별 비율만 다름)
- 변환 **전 = 파랑 / 후 = 빨강**, 중간 단계 = 초록, 보조 요소(대칭축, 평행이동 벡터) = 보라·주황. 섹션이 바뀌어도 색의 의미가 유지되므로 학생이 색만 보고 읽을 수 있습니다.
- **모양도 함께 씁니다** — ○ = 변환 전, △ = 변환 후. 색만으로 구분하면 적록색각이상 학생이 읽을 수 없기 때문에 색은 늘 중복 부호화됩니다. 무지개 대응을 켜면 색상 채널을 그쪽이 가져가고, 전/후 구분은 모양이 온전히 떠맡습니다.
- Plotly 축은 `scaleanchor='x'` / `scaleratio=1` 로 **가로세로 비율 1:1 고정**. 회전과 대칭이 눈으로 회전·대칭처럼 보여야 하므로, 이 앱에서 등축 스케일은 미관이 아니라 **정확성 요건**입니다.
- 수식은 `st.latex()` 로 병기해, 조작 중인 그림과 교과서 표기를 학생이 연결하게 합니다.
- 그래프에는 **반드시 `key` 와 `uirevision`** 이 붙습니다. `key` 가 없으면 갱신 때마다 차트가 통째로 다시 마운트되어 번쩍이고, `uirevision` 이 없으면 학생이 확대해 둔 시야가 매번 초기화됩니다. [lab_ui.py](../lab_ui.py) 의 `chart()` 가 `key` 를 인자로 강제해 새 섹션에서 빠뜨릴 수 없게 합니다.

### 정답을 감추는 규약

이 앱의 화법은 "답을 알려주지 않고 질문을 던진 뒤 도구를 쥐여준다" 입니다. 그것을 UI 규약으로 굳혔습니다.

- 정답을 보여 주는 요소(고유값, 회전 중심, 변환의 이름)는 전부 **`st.toggle("🔎 정체 밝히기", value=False)` 뒤**에 둡니다.
- 각 섹션 위아래에 접힌 `🔍 관찰 과제`(질문)와 `✅ 확인`(답) expander를 둡니다.
- 관찰 보조 장치(자취·무지개·잔상)는 성격이 다릅니다 — 답을 감추는 것이 아니라 **보는 방식**을 고르는 렌즈입니다. 켜도 답이 나오지 않고, 질문이 더 잘 보일 뿐입니다.

§1 은 이 규약을 한 단계 더 밀어 **화면을 둘로 나눕니다**(2026-08-05). `🔬 자유 탐구` 는 예전 실험실 그대로이고, `🧭 단계별 탐구` 는 발견해야 할 것을 화면이 먼저 말하지 않도록 **기저 상자·계기판·$\det$ 캡션을 감춘** 3단계 경로입니다. 감추는 것과 지우는 것은 다릅니다 — 저 둘은 §1 이 내건 명제("열은 기저벡터의 상", "넓이비는 행렬식")를 확인하는 유일한 수단이므로 자유 탐구 쪽에 그대로 남아 있고, 단계 모드에서도 학생이 발견을 마치면 `✅ 확인` 에서 되살아납니다.

같은 절에 붙는 원칙이 하나 더 있습니다. **학생의 발견을 채점하는 것은 모델이 아니라 코드입니다.** 챗봇은 학생의 문장을 미리 정해 둔 주장(claim)으로 옮기고 말투를 입힐 뿐이고, 참·거짓은 [section1_transformation_by_matrix.py](../section1_transformation_by_matrix.py) 의 `check_claim()` 이 지금 화면의 행렬로 직접 계산해서 정합니다. 힌트도 모델이 짓지 않고 섹션에 리터럴로 적힌 사다리에서 **다음 한 칸만** 고릅니다. 이 설계 덕분에 키가 없거나 네트워크가 죽어도 판정은 그대로 살아 있습니다.

## 3. 개발 철학

### (a) 즉시성 우선 — 버튼 없는 인터랙션

"계산하기" 버튼이 없습니다. Streamlit 의 재실행 모델에 기대어 **위젯 값을 바꾸는 즉시 그림이 갱신**됩니다. 값과 도형 사이의 인과를 학생이 체감하는 것이 이 앱의 전부이므로, 그 사이에 클릭을 하나라도 끼워 넣지 않습니다.

> 이 조항은 **수학적 조작**(값 ↔ 그림의 인과)에 적용됩니다. 학생이 자기 발견을 문장으로 **제출**하는 것은 그 인과의 일부가 아니라 별개의 행위이므로 명시적인 제출 시점을 갖습니다(§1 챗봇의 `st.chat_input`, Enter 로 제출). 버튼이 새로 생기지는 않았습니다.
섹션 2는 여기서 한 발 더 나아가 `plotly_events` 로 **그래프를 클릭해 초기점을 직접 찍게** 합니다 ([section2_symmetry_rotation.py:144-149](../section2_symmetry_rotation.py#L144-L149)).

### (b) 표현력 우선 — 자유 입력을 허용한다

섹션 3은 도형의 자취(`x**2 + y**2 == 1`)와 복소함수(`(z - 1j)**2`)를 **사용자가 파이썬 식으로 직접 타이핑**하게 합니다. 드롭다운으로 미리 정해둔 몇 개의 도형만 제공했다면 "실험실"이 아니라 시연 자료가 됐을 것입니다.
곱은 `*`, 제곱은 `**`, 허수는 `1j` 라는 파이썬 표기법을 학생에게 그대로 가르치는 쪽을 택했고, 그 규칙을 입력창 바로 위에 보라색 경고로 명시합니다.

**이 표현력은 `eval` 없이 지킨다.** 초기 구현은 입력 문자열을 그대로 `eval` 했고, 그것은 로컬 실행을 전제로 한 임시방편이었습니다. 지금은 [expression_parser.py](../expression_parser.py) 가 두 단계로 처리합니다.

1. **Python `ast` 로 파싱해 허용 목록에 없는 구문을 전부 거부한다.** 속성 접근(`x.__class__`), 첨자, 람다, 컴프리헨션, 문자열, 대입이 여기서 막힙니다. 이것이 실질적인 방어선입니다.
2. **통과한 식만 sympy 로 넘겨 numpy 벡터 함수로 컴파일한다.**

순서가 중요합니다. sympy 의 `parse_expr` 는 내부적으로 `eval` 을 쓰므로 **단독으로는 안전하지 않습니다.** 1단계를 반드시 먼저 통과시켜야 합니다.

교체하면서 표현력은 오히려 넓어졌습니다 — 부등식(`y > x**2`), 조건 결합(`&`, `|`, `and`, `or`), 연쇄 비교(`0 < y < 1`), `sin`·`exp`·`conj`·`arg` 등의 함수, 허수 표기 `i`, 그리고 옛 코드가 열어 두었던 `np.` 접두 호환이 모두 지원됩니다. 등식은 여전히 격자 간격에 비례한 허용오차 `eps` 로 근사 판정하는데, 이는 sympy 표현식 트리에서 `Eq(L, R)` 를 `Abs(L-R) < eps` 로 바꿔 넣는 방식으로 유지했습니다.

### (c) 학생이 틀린 값을 넣어도 앱이 죽지 않는다

교육용 도구의 사용자는 반드시 이상한 값을 넣습니다. 그래서 방어가 계산 정확성만큼 중요하게 다뤄집니다.

- 섹션 3은 정의역을 **자동 추정**합니다. 범위를 8부터 2씩 넓혀 가며 최대 10회 재시도해, 사용자가 범위를 몰라도 도형이 화면에 잡히게 합니다 ([section3_complex_plane.py:71-96](../section3_complex_plane.py#L71-L96)). 등식 `==` 은 부동소수점으로 정확히 만족될 수 없으므로 격자 간격에 비례한 허용오차 `eps` 로 근사 판정합니다. 수식 컴파일은 이 반복 **밖에서 한 번만** 합니다 — 문법 오류라면 10번 시도해도 결과가 같으므로, 재시도해야 할 것은 격자 범위뿐입니다.
- 실패하면 예외를 흘리지 않고 **학생이 읽을 수 있는 한국어 메시지**를 돌려줍니다. 파서는 `ExpressionError` 에 원인을 담아(`"쓸 수 없는 함수입니다: 'foo'"`, `"모르는 이름입니다: 'zzz'"`) 무엇을 고쳐야 하는지까지 알려 줍니다.
- 파서는 `2**99999` 나 `10**10**10` 처럼 **거대 정수를 만들어 앱을 멈추게 하는 입력**도 거부합니다. 상수 지수는 float 영역에서만 크기를 가늠하므로, 검사 자체가 폭발하지 않습니다.
- 섹션 2의 `draw_axis()` 는 각도가 `None` 이거나 비유한값이면 45°로 되돌리고, 기울기 `|a| > 1` 일 때는 축을 x기준이 아닌 y기준으로 그려 **선이 화면 밖으로 사라지지 않게** 합니다 ([section2_symmetry_rotation.py:92-108](../section2_symmetry_rotation.py#L92-L108)). 커밋 `b6457ae 계속 헤매는 중. y=ax선이 안 보임` 이 이 코드가 생긴 경위입니다.
- 섹션 1은 축 범위를 데이터에서 계산하되 **상한 20으로 클램프**해, 극단적인 행렬을 넣어도 그림이 점 하나로 붕괴하지 않게 합니다.

### (d) 정직한 이력을 남긴다

커밋 메시지가 `08032121 계속 헤매는 중`, `08032237 내가 최선`, `5c9e0a2 (4) 완성일보직전` 처럼 **작업 시각과 당시의 진행 상태를 그대로** 적습니다. 정제된 커밋 로그보다 시도와 실패가 보이는 로그를 남기는 방식이며, 학습 과정 자체가 산출물의 일부인 프로젝트 성격과 일치합니다.
같은 맥락에서 `backup/app_backup.py`(분리 이전 단일 파일)와 `dash_symmetry_tool.py`(Dash 로 섹션 2를 만들어 보다 Streamlit 으로 회귀한 흔적)도 **지우지 않고 남겨** 두었습니다. 현재 `app.py` 에서 import 되지 않으므로 동작에는 영향이 없습니다. 다만 `backup/app_backup.py` 에는 교체 이전의 `eval` 이 그대로 남아 있으므로, **거기서 코드를 되살려 쓰지 마세요.**

### (e) 도구는 가볍게, 진입 장벽은 낮게

- **Streamlit 단일 선택.** Dash 로 섹션 2를 만들어 본 결과(`dash_symmetry_tool.py`, 콜백·`Input`/`Output` 배선 필요)보다, 위에서 아래로 읽히는 Streamlit 스크립트가 이 규모에 맞다고 판단해 회귀했습니다.
- **Docker 제거.** 원본은 GitHub Codespaces용 Streamlit 템플릿 fork 라 `.devcontainer/` 를 포함했고, 그 파일 때문에 VS Code 가 컨테이너 실행을 요구했습니다. 앱 자체는 Docker 에 전혀 의존하지 않으므로 `e549bbe` 에서 제거하고 **venv 만으로 어떤 IDE에서든 동일하게** 개발하도록 정리했습니다.
- **의존성 최소.** `streamlit`, `numpy`, `plotly`, `sympy` **넷뿐**입니다. 학생이 `pip install -r requirements.txt` 한 줄로 끝내야 합니다. 섹션이 넷에서 여덟으로 늘었지만 의존성은 오히려 줄었습니다 — `matplotlib` 은 죽은 코드였고(모든 섹션이 Plotly 로 그립니다), `streamlit-plotly-events` 는 Streamlit 이 기본 제공하는 `on_select` 로 대체했습니다. 다만 그 기능들 때문에 `streamlit>=1.60` 하한이 필요합니다.
- **테스트도 도구를 늘리지 않는다.** [test/](../test/) 의 검증 스크립트들은 pytest 없이 `python test/xxx.py` 로 그냥 돌아갑니다. 통과하면 `ALL PASS` 와 종료 코드 0. 검증 하나 때문에 학생이 테스트 러너 사용법부터 배워야 하는 상황을 만들지 않습니다.
- **검증은 코드가 아니라 주장을 겨눈다.** 각 섹션이 내세우는 명제를 직접 잽니다 — 넓이비가 정말 $\lvert\det\rvert$ 인지, 평행한 두 거울이 정말 간격의 2배만큼 옮기는지, 뫼비우스의 상이 정말 원이나 직선인지(SVD 로 원·직선 일반형에 맞춰 잔차를 잽니다). 화면에 적어 둔 문장이 틀리는 것이 이 프로젝트에서 가장 나쁜 실패이기 때문입니다.
  [test/test_section1_discovery.py](../test/test_section1_discovery.py) 는 여기서 한 발 더 나갑니다 — 명제뿐 아니라 **수업 설계가 성립할 조건**까지 잽니다. 학생에게 보여 줄 두 행렬의 붕괴 기울기가 우연히 같아지면 비교 국면이 무의미해지고, 힌트 문구를 손보다 정답 낱말이 섞여 들어가면 발견이 사라지므로, 그 둘도 실패로 처리합니다.
- **섹션 화면은 헤드리스로 검증한다.** [test/test_sections_render.py](../test/test_sections_render.py) 는 Streamlit 의 `AppTest` 로 여덟 섹션을 띄우고 학생이 실제로 칠 법한 잘못된 입력을 넣어 봅니다. 브라우저가 필요 없습니다.
- **환경은 언제든 버릴 수 있는 것으로 취급.** `.venv/`, `__pycache__/` 는 커밋하지 않으며, 꼬이면 통째로 지우고 다시 만드는 것이 정상 절차입니다.

## 5. 향후 방향

이 프로젝트에 기여하거나 이어받을 때 지켜 주었으면 하는 우선순위입니다.

1. **교육적 명확성 > 코드 우아함.** [lab_ui.py](../lab_ui.py) 로 배관을 옮길 때 그은 경계를 지키세요 — 수학과 학생이 읽는 문구는 섹션에 남습니다. 섹션 파일만 읽고 그 수업이 이해되지 않는다면 그 추출은 잘못된 것입니다.
2. **섹션 독립성을 깨지 마세요.** 새 실험을 추가할 때는 `sectionN_*.py` 에 `run_*()` 하나를 만들고 [app.py](../app.py) 에 분기 한 줄을 더하는 기존 패턴을 따릅니다. 수학이 다른 섹션과 겹쳐도 **복사하는 편이 낫습니다** — 대신 두 복사본이 같은 답을 내는지 테스트로 묶어 두세요(§4·§7 의 `fixed_point` 가 그 예).
3. **시각 관용구를 유지하세요.** 파랑=변환 전 / 빨강=변환 후 + ○/△ 모양, 1:1 등축 스케일, 그래프마다 `key` 와 `uirevision`, 그림 옆의 `st.latex` 병기.
4. **답을 먼저 말하지 마세요.** 정답은 `🔎 정체 밝히기` 토글 뒤에 두고, 학생이 추측할 수단을 그 앞에 두세요. §4 의 고정점이 그 형태입니다 — 추측 → 앱이 검증 → 공식 확인.
5. **파서의 허용 목록을 넓힐 때는 신중하게.** [expression_parser.py](../expression_parser.py) 의 `ALLOWED_FUNCTIONS` 에 이름을 더하는 것은 안전하지만, `_normalize` 의 노드 화이트리스트를 푸는 것은 보안 경계를 무는 일입니다. 특히 **속성 접근(`ast.Attribute`)을 일반적으로 허용해서는 안 됩니다** — 현재의 `np.` 셔임처럼 좁게 제한된 형태만 두세요. 파서를 건드렸다면 `python test/test_expression_parser.py` 를 돌려 `ALL PASS` 를 확인하세요.
6. **모델에게 판정을 맡기지 마세요.** §1 챗봇의 경계는 이렇습니다 — 모델은 학생 문장을 claim 으로 **옮기기만** 하고, 참·거짓은 `check_claim()` 이 숫자로 정하며, 힌트는 섹션에 적힌 사다리에서 **고르기만** 합니다. 이 계획의 초안에는 "붕괴직선은 상직선과 직교한다" 같은 거짓 명제가 셋 있었고(대칭행렬만 보면 참으로 보입니다), 모델도 똑같이 틀립니다. 프롬프트를 고칠 때 이 경계를 무는지 먼저 확인하세요. `python test/test_section1_discovery.py`
7. **입력 검증은 죽지 않는 방향으로.** 예외를 던지기보다 기본값으로 되돌리고 한국어로 안내하는 기존 방식을 따릅니다. 새 섹션을 만들면 [test/test_sections_render.py](../test/test_sections_render.py) 의 `MENUS` 에 추가해 그 성질이 지켜지는지 확인하세요.
